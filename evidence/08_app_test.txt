# Evidence 08: banker app regression test (Streamlit AppTest against the live Lakebase views)
# Captured 2026-11-19T13:36:56Z. Synthetic data only; user identities redacted.

Bug reported in the deployed app: in Customer 360, choosing another customer snapped back to the first one.
Cause: the customer list was ordered by expected_clv_uplift only (738 rows, 736 distinct values), so tied rows could come back in a different order on each fresh connection; the selectbox had no key, so a changed option order reset it to the first customer.
Fix: deterministic ORDER BY (expected_clv_uplift DESC, customer_360_id) and a stable widget key.
